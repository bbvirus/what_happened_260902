# /stock-impact-check

**이 작업을 인라인으로 하지 않는다.** 반드시 `Agent`를 두 번, 순서대로 호출한다:
`search_news` → (그 산출물을 입력으로) → `estimate_stock_impact`.

## 트리거

기업명 + 캐주얼한 질문 형태로 물으면 자동으로 이 스킬을 쓴다. 예:
- "[기업명] 좋은 소식 있나?"
- "[기업명] 무슨 일이야?"
- "[기업명] 요즘 어때?", "동향 어때?" 등 유사 표현

사용자가 **뉴스만** 원하는 게 명확하면(예: "[기업명] 뉴스 찾아줘", "최근 뉴스 정리해줘") `search_news`만 단독 호출하고 이 스킬로 확장하지 않는다 — 주가에 좋은지 나쁜지를 묻는 뉘앙스가 있을 때만 체이닝한다.

## 절차

### 1. 기업명 확인

사용자 발화에서 기업명을 확정한다. 여러 기업이 언급되어 모호하면 사용자에게 묻는다.

### 2. search_news 호출

`Agent`를 `subagent_type: "search_news"`로 호출한다. 프롬프트에 기업명을 명시한다.

반환 결과에서 **산출물 파일 경로** (`output/{YYYYMMDD}/{기업명}-news-{YYYYMMDD}.md`)를 확보한다.
뉴스가 0건이면 여기서 멈추고 그 사실을 사용자에게 알린다 — `estimate_stock_impact`는 호출하지 않는다.

### 3. estimate_stock_impact 호출

`Agent`를 `subagent_type: "estimate_stock_impact"`로 호출한다. 프롬프트에 2단계에서 얻은
**산출물 파일 경로를 입력으로 명시**한다. 이 에이전트는 `WebSearch`/`WebFetch` 권한이 없으므로
직접 뉴스를 재검색하게 하지 않는다 — 반드시 2단계 산출물을 읽게 한다.

### 4. 결과 안내

두 산출물 파일 경로(뉴스 목록, 주가 영향 추정)를 모두 사용자에게 알린다. 사용자의 원 질문이
"좋은 소식/나쁜 소식"류였다면, 영향 추정 결과(긍정/부정 판단 + 근거)를 요약해 바로 이어서 보여준다.
