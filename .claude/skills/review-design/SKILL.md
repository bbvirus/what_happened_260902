# /review-design

**이 검증을 인라인으로 하지 않는다.** 반드시 `Agent`(subagent_type: `design-reviewer`)를 호출한다.
스스로 검증하고 스스로 통과 판정하면 레이어 2가 무의미해진다.

## 절차

### 1. 입력 정리 (호출 전)

| 필요 | 비고 |
|---|---|
| 변경된 파일 목록 | 이번 작업에서 실제로 손댄 파일 전부 |
| 원래 요청 내용 | 범위 일치 판정의 기준이 된다. 요약하지 말고 원문을 넘긴다 |

### 2. 에이전트 호출

`Agent`를 `subagent_type: "design-reviewer"`로 호출한다. 프롬프트에 반드시 포함할 것:

- 변경 파일 목록
- 원래 요청 원문
- "6개 항목을 모두 실행하고, 실행하지 못한 항목은 PASS가 아니라 `N/A(이유)`로 적으라"
- "파일을 수정하지 말고 판정만 하라"

### 3. 결과 처리

| 판정 | 다음 행동 |
|---|---|
| PASS | 완료를 선언할 수 있다 |
| FAIL | **완료를 선언하지 않는다.** FAIL 항목을 담당 에이전트에 넘겨 수정한 뒤 이 스킬을 다시 실행한다 |

- FAIL을 "대체로 통과"로 보고하지 않는다. (원칙 4)
- 판정 표를 사용자에게 그대로 보여준다. 항목별 근거를 요약으로 덮지 않는다
- 레이어 3 hook이 막은 항목을 사람 판단으로 통과시키지 않는다. (3중 레이어 계약)
