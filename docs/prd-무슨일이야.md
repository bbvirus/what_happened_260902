# PRD — 무슨일이야

**한 줄 소개**: 관심 기업명을 입력하면 최신 뉴스를 종합해 그 소식이 주가에 호재인지 악재인지 한눈에 보여주고, 원하면 근거가 된 뉴스 5건을 자세히 확인할 수 있는 모바일 웹 서비스.

**배경**: 주식 투자자는 관심 종목에 새 소식이 뜰 때마다 "이게 좋은 소식인지 나쁜 소식인지"를 스스로 판단해야 한다. 이미 이 프로젝트에는 `search_news`(최신 뉴스 5건 검색) → `estimate_stock_impact`(뉴스별 긍정/부정 판단 + 5건을 다수결로 집계한 종합의견 1개)를 자동으로 체이닝하는 `stock-impact-check` 스킬이 구현되어 있다. 이 PRD는 그 결과를 웹 UI로 노출하는 서비스를 정의한다.

**출처 구분**: 아래 컴포넌트·토큰 목록은 `src/components`, `src/tokens`를 직접 확인해 존재를 확인한 값이다. 백엔드 연동 방식(에이전트 체이닝을 웹 요청에 어떻게 연결할지)은 이번 PRD 범위에서 다루지 않기로 했다 — "리스크 및 메모"에 기록해둔다.

---

## 타겟 사용자

- **주 타겟**: 국내 주식에 개인 투자 중이며, 보유·관심 종목의 뉴스를 매일 확인하는 개인 투자자
- **특성**:
  - 출퇴근 시간 등 짧은 시간에 모바일로 종목을 체크하는 습관이 있다
  - 애널리스트 리포트나 긴 기사를 읽을 시간은 없고, "이 소식이 좋은 건지 나쁜 건지"를 빠르게 알고 싶어 한다
  - 여러 종목을 돌아가며 확인하므로, 검색 → 결과 확인까지의 과정이 짧고 반복하기 쉬워야 한다
- **핵심 사용 시나리오**: "삼성전자 요즘 무슨 일이야?"라는 궁금증이 생겼을 때, 앱을 열고 기업명만 치면 종합 판단을 바로 얻고, 더 알고 싶으면 근거 뉴스까지 파고든다

## 핵심 기능 (MVP)

**2026-09-02 변경**: 메인 화면에 5건의 뉴스를 전부 나열하던 기존 방식을 버리고, 메인은 "종합의견 요약"만 보여주는 화면으로 바꾼다. 개별 뉴스 5건은 별도 화면(`/details`)으로 옮긴다.

| # | 기능 | 설명 |
|---|---|---|
| 1 | 기업명 입력 | 텍스트 입력 필드에 기업명을 입력한다 |
| 2 | 조회 실행 | 버튼 클릭으로 `stock-impact-check` 스킬을 실행한다 (내부적으로 `search_news` → `estimate_stock_impact` 순차 실행. 이제 `estimate_stock_impact`는 뉴스별 판단 5건과 함께 다수결로 집계한 종합의견 1개(긍정/중립/부정 + 근거 1줄)도 함께 반환한다) |
| 3 | 진행 상태 표시 | 조회에는 수십 초 이상 걸릴 수 있어(참고: 테스트 실행 시 `search_news` 약 4분, `estimate_stock_impact` 약 40초), 대기 중임을 알리는 상태 표시가 필요하다. 별도 로딩 컴포넌트 없이 **"잠시만 기다려주세요.."** 텍스트를 화면에 노출하는 것으로 대체한다 |
| 4 | **[변경] 종합 결과 노출 (메인 화면)** | 뉴스 5건 목록 대신 다음 3가지만 보여준다: ① 종합의견 배지 1개(긍정/중립/부정), ② 종합의견 근거 요약 1줄, ③ 화면 최하단의 판단별 이미지(`src/images/positive_result_image.jpg` · `neutral_result_image.jpg` · `negative_result_image.jpg` 중 종합의견에 맞는 1장) |
| 5 | **[신규] 자세히 알아보기** | 종합 결과 아래에 "자세히 알아보기" 버튼을 둔다. 클릭하면 `/details`로 이동하며, 그 화면에서 예전 메인 화면이 보여주던 뉴스 5건 카드(제목·링크·유형·판단·확신도·근거)를 그대로 보여준다 |
| 6 | 빈 결과 처리 | 관련 뉴스가 0건이면 그 사실을 그대로 보여준다 — 이 경우 종합의견·이미지·자세히 알아보기 버튼도 함께 생략한다 (판단할 근거 자체가 없으므로) |
| 7 | 한계 고지 | "콘텐츠 기반 추정이며 투자 권유가 아니다"라는 문구를 결과가 있는 화면(메인·상세 둘 다)에 상시 노출한다 |

**MVP 제외 (Out of Scope)**:
- 실시간 주가 시세·차트 연동
- 여러 기업 동시 비교, 관심 종목 목록/즐겨찾기
- 로그인, 검색 히스토리 저장, 개인화
- 다국어 지원

## 화면 흐름 (2개 화면)

```
[메인 화면: /main]
[상단바: "무슨일이야"]
        ↓
[기업명 입력 필드] + [조회 버튼]
        ↓ (조회 중)
[진행 상태 표시: "잠시만 기다려주세요.."]
        ↓ (완료, 뉴스 1건 이상)
[종합의견 배지: 긍정/중립/부정]
[종합의견 근거 요약 1줄]
[하단 고지: "콘텐츠 기반 추정이며 투자 권유가 아닙니다"]
[자세히 알아보기 버튼]
        ↓ (화면 최하단)
[판단별 이미지: positive/neutral/negative 중 1장]

        │ "자세히 알아보기" 클릭
        ▼

[상세 화면: /details]
[상단바: "무슨일이야"] + [뒤로가기 → /main]
[뉴스 카드 1] 제목 · 판단 배지(긍정적/부정적/중립·불확실) · 확신도 · 근거
[뉴스 카드 2] ...
...
[뉴스 카드 5]
[하단 고지: "콘텐츠 기반 추정이며 투자 권유가 아닙니다"]
```

뉴스 0건(빈 결과)일 때는 메인 화면에 안내 문구만 보이고, 종합의견·이미지·자세히 알아보기 버튼이
전부 생략된다 — `/details`로 넘어갈 근거 자체가 없기 때문이다.

바텀 내비게이션은 쓰지 않는다 — 화면이 늘었지만 탭으로 나눌 성격의 구조가 아니라 순차 흐름(입력 → 요약 → 상세)이다.

## 화면 간 데이터 전달 (결정됨)

메인에서 조회한 결과를 `/details`가 다시 보여주기 위해, **URL 쿼리 파라미터로 기업명만 넘기고
(`/details?company=삼성전자`), `/details`가 같은 mock 조회 함수(`fetchMockStockImpact` 계열)를
독립적으로 다시 호출**하기로 확정했다 (2026-09-02 결정). 새로고침이나 주소 직접 입력에도 안전하고
구현이 단순하다는 것이 근거다.

백엔드는 나중에 별도로 만들 예정이라(위 "리스크 및 메모" 참조), 지금은 이 mock 재조회 방식으로
충분하다. 실제 백엔드 연동 시 재조회 비용 문제가 생기면 그때 다시 검토한다.

## 사용할 기존 토큰·컴포넌트 (재사용 우선)

`src/components`, `src/tokens`에 이미 존재를 확인한 것만 적는다. 새로 만들 컴포넌트는 없다 — 로딩 상태는 텍스트로, 판단 배지는 기존 컴포넌트와 색상 토큰 조합으로 표현한다.

| 목적 | 재사용할 기존 컴포넌트 |
|---|---|
| 상단 타이틀 바 | `OSBarTopNavigation` |
| 상세 화면 뒤로가기 헤더 | `Header` (`hasSlotStart`, `onSlotStartClick`으로 `/main` 이동) |
| 기업명 입력 필드 | `TextFieldText` (또는 `TextFieldTextSet`) |
| 조회 실행 · 자세히 알아보기 버튼 | `Button` |
| 결과 카드 제목/섹션 헤더 | `TextSetTitle` |
| 뉴스 카드 간 구분선 | `Divider` |
| 판단 결과 시각 표시(긍정/부정/중립 아이콘) | `Icon` |
| 판단별 이미지 | 새 컴포넌트 아님 — `src/images/{positive,neutral,negative}_result_image.jpg` 정적 asset을 일반 `<img>`로 노출 (사용자가 2026-09-02 직접 추가) |
| 색상·타이포·간격 | `src/tokens/colors.tokens.css`, `typography.tokens.css`, `spacing.tokens.css`, `design-tokens.css` |

## 판단 배지 색상 (결정됨)

`src/tokens/colors.tokens.css`를 직접 확인해 아래와 같이 확정했다. 새 토큰이 필요한 지점은
"필요한 토큰이 없으면 raw 값 대신 토큰을 먼저 추가한다" 원칙에 따라 새 값을 지어내지 않고
**이미 존재하는 primitive 값**을 semantic 레이어로 노출하는 것으로만 처리한다.

| 판단 | 배경 | 글씨 | 비고 |
|---|---|---|---|
| 긍정(적) | `--informative-light-10` (`#edf2fd`, 옅은 파랑) | `--color-text-primary` (검정) | 부정(빨강)과 대비되도록 파랑으로 변경(2026-09-02). 배경은 **이미 있는 primitive**지만 이를 가리키는 semantic 토큰(`--color-bg-informative-subtle`, 이미 추가됨)을 쓴다 |
| 중립(·불확실) | `--color-bg-secondary` 또는 `--color-bg-tertiary` (연한 회색) | `--color-text-primary` (검정) | **기존 토큰 그대로 재사용, 신규 토큰 불필요** |
| 부정(적) | `--negative-light-900` (`#450202`, 매우 진한 톤) | `--color-text-inverse` (흰색) | 배경은 **이미 있는 primitive**지만, 이를 가리키는 semantic 토큰(`--color-bg-negative-strong`, 이미 추가됨)을 쓴다 |

**메인의 종합의견 배지와 상세 화면의 개별 판단 배지는 같은 3색 팔레트를 재사용하되 레이블 문구만
다르다** — `estimate_stock_impact` 에이전트 스펙과 동일한 구분이다.
- 종합의견(메인): "긍정 / 중립 / 부정"
- 개별 판단(상세): "긍정적 / 부정적 / 중립·불확실"

## 성공 기준

- **기능 완료(메인)**: 기업명 입력 → 조회 실행 → 종합의견 배지 + 근거 요약 1줄 + 판단별 이미지가 `estimate_stock_impact` 산출물의 종합의견 내용과 1:1로 일치한다
- **기능 완료(상세)**: "자세히 알아보기" 클릭 → `/details`에서 뉴스 5건(제목/링크/유형/판단/확신도/근거)이 산출물 내용과 1:1로 일치한다
- **이미지 매핑 정확성**: 종합의견이 긍정/중립/부정일 때 각각 `positive_result_image.jpg`/`neutral_result_image.jpg`/`negative_result_image.jpg`가 정확히 매핑되어 노출된다 (뒤바뀌거나 누락되지 않는다)
- **모바일 뷰**: 360px~430px 폭 뷰포트에서 레이아웃 깨짐(가로 스크롤 발생, 텍스트 잘림, 버튼 겹침) 없이 표시된다 — 이미지 영역도 포함
- **일관성(이 저장소의 완료 기준)**: 이 프로젝트 `CLAUDE.md` 목적 1·3 기준을 그대로 따른다 — 화면 구현 시 raw 값 0건, `npm run typecheck` · `npm run build` 통과
- **신뢰성 고지**: 결과가 있는 모든 화면(메인·상세)에 "투자 권유 아님" 문구가 빠짐없이 노출된다
- **정직한 결과 처리**: 뉴스가 0건이면 종합의견·이미지·자세히 알아보기 버튼을 억지로 채우지 않고 전부 생략한 채 그 사실만 보여준다

## 리스크 및 메모

- **[메모] 백엔드 연동은 이번 범위에서 다루지 않음**: `stock-impact-check`는 Claude Code의 서브에이전트 체이닝(`Agent` 도구)으로 동작한다. 이를 일반 웹사이트 요청/응답으로 어떻게 연결할지(예: Claude Agent SDK로 서버에서 실행 등)는 **추후 별도 작업으로 진행**하기로 했다 (2026-09-02 결정). 프론트엔드 설계·구현은 이 연동이 어떤 방식으로든 결과 JSON/텍스트를 돌려준다는 가정 위에서 먼저 진행한다.
- **응답 지연**: 실제 테스트에서 `search_news` 실행에 약 4분, `estimate_stock_impact`에 약 40초가 걸렸다. "잠시만 기다려주세요.." 문구만으로는 긴 대기 중 사용자가 이탈할 수 있으니, 백엔드 연동 작업 시 진행률 표시나 타임아웃 정책을 함께 검토한다.
- **[메모] 화면 간 데이터 전달**: 위 "화면 간 데이터 전달" 절 참조 — URL 쿼리 파라미터(`?company=`) 방식으로 확정했다.
- **[신규] 이미지 자산 관리**: `src/images/*.jpg` 3장은 사용자가 직접 추가한 것이며(2026-09-02), 이 PRD가 만들어내는 산출물이 아니다. 파일이 삭제·이동되면 메인 화면 최하단 이미지가 깨지므로, 구현 시 파일 존재를 전제로 import한다.
