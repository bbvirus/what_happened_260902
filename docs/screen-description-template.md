# 화면 기획문서 Description 템플릿

**출처**: Figma `IMtjxuW0MaxRzGEi5JKJWd`, node `2081:23098` ("로그인 안내" 기획문서)
**용도**: 다른 화면을 기획할 때 이 구조를 그대로 복제해서 쓴다.

이 문서는 템플릿이다. 규칙 판단 기준은 여전히 `CLAUDE.md`이고, 여기서는 그 규칙을
적용하기 전 단계인 **기획 문서의 형식**만 정의한다.

---

## 1. 헤더 블록

기획문서 최상단에 오는 메타 정보. 원본에서 실제로 렌더링된 필드만 포함한다.

| 필드 | 원본 예시 값 | 설명 |
|---|---|---|
| 화면 | 로그인 안내 `[V1.0]` | 화면 이름 + 버전 배지 |
| 화면 ID | `LG_020101_P01` | 화면 고유 식별자 |
| 화면타입 | React | 구현 플랫폼/기술 |
| LOCATION | U+ 라이프핏 > 패키지 추천 > 로그인 안내 | 정보구조상 위치 (계층을 `>`로 구분) |
| 화면구분 | Popup | 화면/팝업/바텀시트 등 화면 유형 |

> **참고**: 원본 레이어 이름에는 `화면 경로`, `요구사항 ID`라는 필드도 존재했지만,
> 이 문서 인스턴스에서는 각각 `LOCATION`, `화면구분` 값으로 대체되어 렌더링되어 있었다.
> 즉 마스터 템플릿에는 5개 필드(화면/화면ID/화면타입/화면경로/요구사항ID)가 있고,
> 화면 성격에 따라 `화면경로` 자리에 LOCATION을, `요구사항ID` 자리에 화면구분을 넣는 식으로
> **자유롭게 재정의해서 써도 되는 슬롯**으로 보인다. 새 화면 기획 시 다섯 필드 중
> 해당 화면에 의미 있는 것만 채운다.

## 2. Description 표 구조

헤더 아래에 번호가 매겨진 행(01, 02, 03…)이 오고, 각 행은 **주제 하나**를 담당한다.
행 개수는 화면마다 다르다 — 정해진 개수가 아니라 필요한 만큼 늘린다.

원본(로그인 안내 팝업)에서 확인된 3개 행 패턴:

### 01 — 정의 / 노출 조건

```
[<컴포넌트명> 정의]
<한 상태에서 어떤 트리거로 이 화면/팝업이 뜨는지, 뜬 뒤 상태가 어떻게 유지·복귀되는지>

노출 조건 : <트리거 조건>
닫기 : <닫는 방법 — 없으면 "없음" 명시>
배경 : <dim 처리 여부, dim 클릭 시 동작>
```

### 02 — 문구 영역

```
문구 영역
문구는 <고정값 / 동적값> 이며, <조건에 따라 바뀌는지 여부>

[노출 데이터]
정의 : <이 영역이 전달하는 정보의 목적>

타이틀 · "<실제 문구>"
보조 문구 · "<실제 문구>"

타이틀은 <토큰명> 토큰, 보조 문구는 <토큰명> 토큰을 사용한다
<줄바꿈/말줄임 규칙>
```

### 03 — 액션 버튼 / 인터랙션

```
액션 버튼

[<버튼 라벨>] Type=<Primary/Secondary/...> / Size=<xl/lg/...>
- 클릭 시 <이동 경로 또는 동작>
- <상태 유지/초기화 규칙>

[<버튼 라벨>] Type=<...> / Size=<...>
- <동작>

[확인 필요]
- <미결정 사항을 그대로 남긴다. 임의로 결정하지 않는다>
```

## 3. 사용 규칙

- **행 번호는 순번일 뿐 의미를 갖지 않는다.** 화면에 필요한 주제 수만큼 01, 02, 03…으로 늘린다.
  (예: 리스트 화면이면 `04 — 리스트 아이템 규칙`, 폼 화면이면 `04 — 입력 검증`처럼 추가)
- **문구는 항상 실제 문자열을 그대로 인용한다.** 요약하거나 의역하지 않는다.
- **토큰명을 언급할 때는 실제 디자인 시스템 토큰명을 쓴다.** 추정한 이름을 넣지 않는다 —
  모르면 "토큰 미확인"이라고 쓰고 비워둔다.
- **미결정 사항은 `[확인 필요]`로 명시하고 임의로 결론 내리지 않는다.** 이 항목이 있으면
  구현(Clarify 단계)에서 반드시 질문으로 다시 올라와야 한다.
- **화면 간 중복 배치 주의**: 원본 문서에서 Description 표가 캔버스에 실수로 복제되어
  두 번 존재했다 (`2081:23188`, `2151:31632` — 내용 100% 동일). 새 기획 문서를 만들 때
  프레임을 복제한 뒤 내용이 실제로 갱신됐는지 확인한다.
